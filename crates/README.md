# Crates

The workspace's crates, one folder per layer: `crates/<layer>/<crate>/`, where the crate's folder is its package name
without `specforge-`. [ARCHITECTURE.md](../ARCHITECTURE.md) says what the layers are for and why the tree has this
shape.

## The rule

A crate depends only on crates in its own layer or a layer below it, through normal and build dependencies.
Dev-dependencies are exempt. `cargo gate`'s `layers` check enforces it; an exception needs an ADR and an entry in the
check's allow list ([ADR 0084](../docs/adr/0084-a-crates-layer-is-its-folder.md)).

## Adding or moving a crate

1. Put it in the layer whose line below says what it is. Every crate it depends on must sit in that layer or lower.
2. Give its `Cargo.toml` a one-line `description` saying what it owns, and open each crate root (`src/lib.rs`,
   `src/main.rs`) with a `//!` doc saying what the crate is.
3. Add it to the root `Cargo.toml` `members`, and add a `module` titled with its package name to
   [spec/product/modules.spec](../spec/product/modules.spec). `cargo gate`'s `spec-modules` check says what that module
   must read.
4. Run `cargo gate crate-map`. It rewrites the tables below and the stack in `ARCHITECTURE.md`.

## The crates

Each line is the crate's `Cargo.toml` `description`. "Outside `crates/`" lists the workspace members that are not
product crates: the repository's tooling and the published Rust test integration.

### `surfaces`

The programs: the specforge CLI, the language server, the MCP server and the package registry server. Each turns its protocol into calls on the layers below.

| Crate | Package | Owns |
|---|---|---|
| [`cli`](surfaces/cli/) | `specforge-cli` | The specforge binary: every command's arguments, the terminal it writes to and asks from, and its exit code, over specforge-ops (ADR 0029) |
| [`lsp`](surfaces/lsp/) | `specforge-lsp` | The language server: open documents held in the project session, published diagnostics, navigation, completion, hover and formatting (ADR 0023, ADR 0043, ADR 0046) |
| [`mcp`](surfaces/mcp/) | `specforge-mcp` | The MCP server: tools, prompts, resources and events, each one typed definition over specforge-ops, served over the stdio transport (ADR 0024, ADR 0062) |
| [`mcp-macros`](surfaces/mcp-macros/) | `specforge-mcp-macros` | Derive macro for specforge-mcp: a tool's or prompt's arguments are one typed definition (ADR 0033) |
| [`registry-server`](surfaces/registry-server/) | `specforge-registry-server` | The package registry server (specforge-registry): the registry contract's routes over SQLite and blob storage, publish authentication and signature checks (ADR 0044, ADR 0061) |
